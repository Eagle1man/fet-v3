# FET v3 — перенос расписания AVTOR → FET

Конвейер: выгрузка AVTOR (`rasp2.csv`, CP1251) → SQLite → `.fet` по схеме
FET 7.10.5 → проверка настоящим `fet-cl` → отчёты.

## Принципы

1. **Ничего не досочиняется.** Нет данных о вместимости аудитории — в `.fet`
   стоит заглушка `999` с пометкой в отчёте, а не выдуманное число.
2. **Каждая активность хранит источник** — период, файл и номер строки
   `rasp2.csv`. В отчёте конфликта эта ссылка видна.
3. **Конфликты не выбрасываются.** Активность остаётся в файле, получает
   вес 50 вместо 100, а человек видит слот и обе строки источника.
4. **Проверка — бинарником FET.** `ElementTree.parse` ничего не доказывает:
   файл может быть валидным XML и невалидным `.fet`.
5. **Детерминизм.** Повторный прогон даёт тот же `.fet`.

## Быстрый старт

```powershell
cd D:\FET_v3
copy .env.example .env      # поправить пути
python -X utf8 run.py etl       # выгрузка AVTOR -> data\schedule.db
python -X utf8 run.py build     # 6 периодов + семестр -> out\fet\*.fet
python -X utf8 run.py validate  # схема + реальный fet-cl (нужен .env: FET_CL)
python -X utf8 run.py report    # out\final_report.md / .xlsx
python -X utf8 run.py audit     # docs\00_audit.md
python -X utf8 run.py ui        # панель: поиск, правка, откат
python -X utf8 run.py all       # всё подряд (без UI)
```

Тесты:

```powershell
python -X utf8 -m pytest
```

## Правила сборки

- **Объединённая лекция** — одна активность с несколькими `<Students>`.
- **Совместное занятие** (один слот, предмет, аудитория, разные преподаватели,
  общие группы) — одна активность с несколькими `<Teacher>`.
- **`Subg`** — параллельная ветка: `Group → Subgroup`, имя `<группа> п<код>`.
  Подгруппа не занимает родительскую группу, иначе параллельные ветки давали
  бы ложный конфликт.
- **Сдвоенная пара** — `Duration=2`, только если следующий слот не занят
  другой активностью тех же студентов/преподавателя/аудитории.
- **Дистант** (аудитория начинается с `.`) — без `<Room>`.
- **Накладка аудитории** — вторая активность получает клон `ауд#2`, факт
  накладки пишется в отчёт.
- **Перекрытие периодов** — дата берётся из более поздней выгрузки.

## Панель и правки

`run.py ui` открывает Tkinter-панель:

- поиск по группе, преподавателю, аудитории и диапазону дат;
- правка даты, пары, аудитории, преподавателя, предмета;
- каждая правка пишется в `change_log` одной транзакцией с изменением строки;
- «Отменить последнюю» возвращает предыдущие значения;
- кнопки «Пересобрать .fet» и «Проверить FET» вызывают те же команды CLI.

Правки **переживают повторный ETL**: `run.py etl` после загрузки применяет
активные записи `change_log` к новым строкам по ключу «период + строка
источника». Если строки в новой выгрузке нет, правка пропускается.

## Ограничения (это не баги, а состояние данных)
- Даты в выгрузке — **2026 год**, хотя каталоги названы `*.27`. Год не
  сдвигается: сдвиг меняет дни недели.
- Выгружены не все недели семестра; покрытие перечислено в
  `docs/00_audit.md`.
- Вместимость и корпус аудиторий в источниках отсутствуют.
- `Преп_*.xls` — это нагрузка преподавателя, а не запреты. Недоступности
  задаются вручную через `FETV3_CONSTRAINTS` (JSON):

```json
{"unavailable": [
  {"kind": "teacher", "name": "Иванов И.И.", "day": "12.01 Пн", "hour": 3}
]}
```

## Требования

Python 3.11+, `xlrd`, `openpyxl`. `fet-cl.exe` 7.10.x — только для проверки,
сборка `.fet` без него работает.
