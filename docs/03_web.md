# Веб-панель на ВМ вуза

Один процесс FastAPI + Jinja2. Без Node.js и сборки фронтенда.
Панель читает `schedule.db`, вызывает тот же конвейер, что и CLI, и
публикует расписание в формате сайта `iubip.ru`.

## Что умеет

| Раздел | Что делает |
|---|---|
| Обзор | периоды, объём, последняя сборка и проверка, выгрузки |
| Занятия | поиск по группе/преподавателю/аудитории/датам, правка с журналом |
| Неделя | сетка группы по неделям, подгруппы помечены |
| Конфликты | слоты, накладки аудиторий, версии строк |
| Публикация | сборка, проверка FET, экспорт, архив, FTP |
| API | `/api/site/groups`, `/api/site/schedule?group=…` |

Долгие операции идут в фоне: страница не висит, статус виден в журнале и
всплывающей плашке.

## Запуск на Windows-ВМ

```powershell
cd D:\FET_v3
copy .env.example .env
# задать FETV3_WEB_PASSWORD и FETV3_WEB_SECRET
.\scripts\start_web.ps1 -Port 8000
```

Открыть `http://<адрес-ВМ>:8000`, войти паролем.

Автозапуск: «Планировщик заданий» → при старте системы →
`powershell.exe -ExecutionPolicy Bypass -File D:\FET_v3\scripts\start_web.ps1`.
Для службы можно использовать NSSM с той же командой.

## Запуск в Docker (Linux-ВМ)

```bash
docker compose up -d --build
```

Что нужно подготовить на хосте:

```
D:\FET_v3\data\schedule.db     # база (создаётся `run.py etl`)
D:\FET_v3\out\                 # результаты сборки и выгрузки
D:\FET_v3\avtor\               # выгрузка AVTOR (Rasp_*/rasp2.csv)
```

`docker-compose.yml` монтирует их в `/data`, `/out`, `/avtor` и поднимает
порт 8000. Проверка живости: `GET /healthz`.

> Проверка `fet-cl` на Linux требует Linux-сборки FET. Если её нет,
> запускайте сборку/проверку на Windows-хосте, а в контейнере оставьте
> только просмотр и публикацию готовых файлов.

## Публикация на сайт вуза

Сайт отдаёт расписание через
`POST /local/templates/univer/include/schedule/ajax/read-file-groups.php`:

- `do=groups` → `{"Академия": {"Группа": 1}}`
- `do=schedule&group=X` → `{"X": ["дд.мм.гггг - дд.мм.гггг", {"10": [...]}]}`

Наш экспорт делает ровно эти структуры (`groups.json`, `data.json`) плюс
автономный просмотрщик и архив.

Три способа размещения:

1. **Своя страница на ВМ (проще всего).**
   Распаковать архив на ВМ, открыть `index.html` через веб-сервер (nginx/IIS).
   С сайта вуза поставить ссылку или `<iframe>` на эту страницу.
   Никаких паролей от сайта не нужно.

   Быстрая проверка локально:

   ```bash
   python -m http.server 8081 -d out/site/<версия>
   ```

   Открыть `http://127.0.0.1:8081/`.

2. **FTP на хостинг вуза.**
   Задать `FETV3_FTP_HOST/USER/PASSWORD/DIR`, нажать «отправить» в строке
   выгрузки. Файлы кладутся в тот каталог, откуда PHP читает расписание
   (уточнить у администратора сайта).

3. **Прокси к API панели.**
   На сервере сайта добавить в nginx:
   `location /schedule-api/ { proxy_pass http://<ВМ>:8000/api/site/; }`
   Тогда JS сайта сможет обращаться к `/schedule-api/groups` и
   `/schedule-api/schedule?group=…` без CORS. Если обращаться напрямую,
   задайте `FETV3_CORS_ORIGINS=https://www.iubip.ru`.

Сопоставление «группа → академия» берётся из `config/site_groups.json`
(снимок `do=groups`). Нет совпадения — группа попадает в
`FETV3_SITE_FACULTY` (по умолчанию «Колледж»).

## Безопасность

- `FETV3_WEB_PASSWORD` обязателен для ВМ. Пустой пароль = панель открыта всем
  (только для отладки, в интерфейсе горит предупреждение).
- `FETV3_WEB_SECRET` — случайная строка, иначе сессии предсказуемы.
- Наружу отдавайте только через HTTPS-прокси (nginx/IIS ARR). Порт 8000
  не должен смотреть в интернет.
- Правки и публикация требуют входа и CSRF-токен. Чтение можно открыть
  (`FETV3_PUBLIC_READ=true`).
- Пароль один на всех: это осознанное ограничение MVP. Роли и LDAP —
  следующий шаг.

## Обслуживание

- Резервная копия: `data/schedule.db` + `out/site/`.
- Обновление кода: остановить сервис, заменить файлы, `pip install .`,
  запустить снова. База и выгрузки не затрагиваются.
- Логи: stdout процесса (systemd/NSSM) или `docker compose logs -f`.
- Одна тяжёлая операция за раз: второй запрос получит сообщение
  «Уже выполняется другая операция».

## Проверка после развёртывания

```bash
curl http://127.0.0.1:8000/healthz
curl -c cookies.txt -d "password=..." http://127.0.0.1:8000/login
curl -b cookies.txt http://127.0.0.1:8000/api/site/groups
```

Если сайт требует cookie `beget=begetok` (защита хостинга), это касается
только запросов к `iubip.ru`, к нашей панели отношения не имеет.
